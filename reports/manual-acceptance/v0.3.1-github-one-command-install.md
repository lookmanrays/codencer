# v0.3.1 GitHub One-Command Install Acceptance

- Branch: `fix/github-one-command-installer`
- Date: `2026-07-07`
- Verdict: GO for patch PR readiness.

## Problem

The previous `scripts/install.sh` defaulted to `BIN_DIR="bin"`, so:

```bash
curl -fsSL https://raw.githubusercontent.com/lookmanrays/codencer/main/scripts/install.sh | sh
```

could install binaries from the caller's current working directory when run
from the repository root. One-command install must be independent of caller cwd
and must install verified GitHub Release artifacts.

## Implementation Summary

- Replaced the implicit caller-cwd `bin/` default with `release-bootstrap`
  mode for stdin/piped installs.
- Added release asset flags:
  - `--version <tag>`
  - `--repo <owner/name>`
  - `--platform <os_arch>`
  - `--install-dir <path>`
  - `--codencer-home <path>`
  - `--download-dir <path>`
  - `--keep-downloads`
  - `--no-download`
  - `--json`
  - `--dry-run`
- Release-bootstrap mode:
  - detects supported platform;
  - resolves latest release when `--version` is omitted;
  - downloads `codencer_<version>_<platform>.tar.gz`, `checksums.txt`, and
    `manifest.json` using `curl -fsSL --retry 3 --proto '=https' --tlsv1.2`;
  - verifies archive SHA256 with `sha256sum` or `shasum -a 256`;
  - verifies `manifest.json` references the selected artifact and SHA256;
  - extracts to a temporary directory;
  - installs `codencer`, `orchestratord`, `codencer-relayd`,
    `codencer-gatewayd`, and `codencer-connectord`;
  - initializes `CODENCER_HOME`.
- Package-local mode is preserved only when:
  - `--bin-dir <path>` is explicit; or
  - the script path proves it is inside an unpacked package with a local
    `bin/` directory.
- Piped/stdin execution cannot determine a package path and therefore cannot
  use package-local mode.
- Windows-native installs fail with:

```text
Windows-native Codencer artifacts are not published yet. Use WSL2/Linux artifact for now.
```

## Review Follow-up Fixes

- The Release Assets workflow now builds and publishes both macOS installer
  platforms selected by `scripts/install.sh`:
  - `codencer_${TAG_NAME}_darwin_arm64.tar.gz`
  - `codencer_${TAG_NAME}_darwin_amd64.tar.gz`
- The publish step now requires Linux amd64 plus both Darwin archives before
  writing `checksums.txt` and `manifest.json`.
- The unpinned latest-release path now wraps the `curl` redirect lookup in an
  explicit failure check, so JSON callers receive the installer JSON error
  contract instead of a raw `curl` exit.
- Regression coverage now proves a failing latest-release `curl` in piped mode
  returns JSON with `ok=false` and the installer error message.
- Regression coverage now proves a post-copy `codencer init --json` failure
  still returns installer JSON with `ok=false` and `partial=true`, without
  leaking child stderr into machine-readable output.
- Regression coverage now proves unsupported auto-detected platforms such as
  Linux arm64 return installer JSON instead of being swallowed by command
  substitution.
- Regression coverage now proves invalid `manifest.json` metadata returns
  installer JSON instead of raw Python verifier output.
- Regression coverage now proves pinned release asset download failures keep
  `curl` stderr out of combined JSON output.
- Regression coverage now proves malformed release archives that lack exactly
  one complete Codencer `bin/` directory return installer JSON.
- Local dual-Darwin snapshot proof passed:
  `make release-snapshot VERSION=v0.3.1-review TARGETS=darwin/arm64,darwin/amd64 REQUIRE_TARGETS=darwin/arm64,darwin/amd64 DIST=<tmp>`.
- The macOS Release Assets job now verifies the `${TAG_NAME}` `dist` artifacts
  with a targeted Python checksum/manifest check instead of running
  `make verify-release`, which would rebuild and overwrite `dist`.
- No tags, releases, or release assets were created or uploaded by this fix.

## Safety

- No `gh` CLI requirement.
- No `sudo`.
- No shell profile edits.
- No process killing.
- No downloaded script execution.
- No caller-cwd `./bin` fallback.
- Sourcing the script runs the installer in a subshell and returns to the
  calling shell.
- Successful tar extraction warnings are suppressed so `--json` stdout remains
  machine-readable even if tar reports harmless timestamp warnings.
